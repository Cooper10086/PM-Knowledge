# Codex 写 Flutter (AI项目构建 - PM 零基础精讲版)

> **本章学习目标**：掌握在 AI 辅助编程时代，利用 Codex 等大模型与 MCP（模型上下文协议）工具链极速生成、构建与测试 Flutter 应用的最佳协同实践。

---

## 📖 1. 本章名词字典 (Glossary for PM)

| 技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Codex** | “让 Codex 帮我写代码” | **“AI 程序员大脑”**。大模型代码生成的核心引擎，负责编写 Dart 代码、排布 UI 页面结构以及编写配置文件。 |
| **MCP** | “连接一下 MCP 插件” | **“AI 程序员的工具箱外接插口”**。Model Context Protocol。让 AI 不仅能动脑写字，还能动手直接控制你本地的终端命令行、运行 iOS 模拟器。 |

| **flutter doctor** | “先跑个 doctor 自检” | **“Flutter 全身扫描自检仪”**。运行此命令可自动检测你电脑上是否缺 Android SDK、是否缺 Xcode，并给出装机补丁说明。 |

## 🧭 2. AI 协同开发 Flutter 核心装备箱 (Toolbox)

在 Vibecoding 时代，您作为产品经理，在让 AI 帮您做 Flutter 开发时，应当拼装出以下这套“多兵种协同工具矩阵”：

```
                    ┌────────────────────────┐
                    │  AI 协作 Flutter 开发   │
                    └───────────┬────────────┘
                                │
         ┌──────────────────────┼──────────────────────┐
         ▼                      ▼                      ▼
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  Codex 编码大脑  │    │  本机命令行工具  │    │  XcodeBuildMCP  │
├─────────────────┤    ├─────────────────┤    ├─────────────────┤
│ 🟩 负责：        │    │ 🟩 负责：        │    │ 🟩 负责：        │
│ 1. 编写 Dart    │    │ 1. flutter run  │    │ 1. 自动定位     │
│ 2. 状态管理/路由 │    │ 2. pub get下载库│    │ 2. 打开 iOS 模拟器│
│ 3. 页面组件拼装  │    │ 3. 编译打包 APK │    │ 3. 排查 Xcode 报错│
└─────────────────┘    └─────────────────┘    └─────────────────┘
```

* **PM 视角解读**：
  * **大脑** 负责设计和写纸面代码（Codex）。
  * **手脚** 负责在电脑上敲键盘运行起来（Flutter CLI）。
  * **眼睛** 负责盯着 iOS 手机模拟器上画出的界面对不对（XcodeBuildMCP）。

## 💻 3. 🚨 重点掌握：如何让 AI 控制你的 iOS 模拟器运行？

很多时候，AI 写了代码，但您不会去 Xcode 里点按按钮。通过 **XcodeBuildMCP**，您可以直接用大白话“声控”AI 帮您编译并在模拟器上运行：

### 💬 推荐的声控指令（Prompts）：
* **指令一：自检**：
  > “使用 `XcodeBuildMCP` 检查当前项目是否能正常在 iOS 模拟器上运行。”
* **指令二：针对 Flutter 项目定位运行**：
  > “使用 `XcodeBuildMCP` 运行 Flutter 工程里的 `ios/Runner.xcworkspace`，指定 scheme 为 `Runner`，并在 iPhone 16 模拟器上打开。”

### ⚙️ AI 收到指令后的自动化动作：
1. 自动扫描你的工作区文件夹，寻找 `.xcworkspace`。
2. 自动检查你电脑上安装的 Xcode 版本和当前可用的 iOS 模拟器型号。
3. 在后台启动模拟器，并在终端执行 `xcodebuild` 编译打包。
4. 将 App 塞进模拟器，让您一眼看到运行效果。
