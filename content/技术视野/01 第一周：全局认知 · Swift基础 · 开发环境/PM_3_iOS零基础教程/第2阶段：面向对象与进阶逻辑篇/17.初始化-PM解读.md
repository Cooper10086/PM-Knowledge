# 17. 初始化与析构 (iOS 基础教程 - PM 零基础精讲版)

> **本章学习目标**：掌握 Swift 类对象出生的“出厂默认设置”构造器 `init` 的写法与重载，以及对象死亡时自动触发的“扫尾方法” `deinit` 的原理。

---

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Initializer (`init`)**| “写个 init 构造函数” | **“新产品出厂设置 / 准生证”**。在类对象出生实例化那一刻，系统必定会自动调用的特殊方法。强制要求在出厂前把所有非空的箱子（属性）都填好，否则不给出生。 |
| **Initialization Safety**| “初始化安全校验” | **“防带病出厂”**。Swift 的安全法则。普通属性定义了就必须有初值。如果研发漏掉了某个必填属性的初始化，编译器直接报错拒绝编译。 |
| **Overloading** | “重载 init 构造方法” | **“多种入场开户方式”**。同一个类定义了多个 `init`。方法名都是 `init`，但由于入参的标签、类型或数量不同，支持从不同入口把对象造出来。 |
| **Destructor (`deinit`)**| “在 deinit 里释放资源” | **“临终扫尾工作”**。析构方法。在类对象被彻底销毁、内存回收的前一刹那，系统自动调用的方法。无法手动呼叫。 |
| **Scope** | “出了大括号作用域了” | **“防泄漏密闭玻璃房”**。大括号 `{}` 圈定的临时局部范围。变量一旦走出大括号的物理界限，就会被系统自动断开引用并彻底回收。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 搞懂 `init` 构造方法如何保底数据安全
* **教程说**：如果一个类有非可选存储属性没有默认值且没有在构造器中完成初始化，会导致编译报错。
* **大白话翻译**：如果你画的图纸规定一个人有 `name` 属性，却既没有写 `name = ""`，也没有在 `init()` 里面给它塞字。那当别人调用 `let p = Person()` 时，内存里就会产生一个“名字是个无意义乱码”的残疾对象。
* 为了绝对的安全，Swift 在编译期就卡死这个逻辑漏洞：**要么直接给默认值，要么写进 `init` 里，否则别想出生！**

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

### 3.1 编写默认构造器 `init`

```swift
class Person {
    var name: String // 没有赋初始默认值
    var age: Int     // 没有赋初始默认值
    
    // 💡 声明构造器 (注意：init 前方绝对不能写 func 关键字)
    init() {
        self.name = "新生儿" // 1. 赶在出厂前，把必填的 name 填好
        self.age = 0       // 2. 把必填的 age 填好
        print("Person 出生")
    }
}

let baby = Person() // 3. 实例化时，括号内没有参数，自动匹配调用无参的 init()
// 控制台打印: Person 出生
// 此时 baby 实例在出厂时自动拥有了 name = "新生儿"
```

### 3.2 构造器重载 (Initializer Overloading)

为了应对多渠道入场创建对象的需求，我们通常重载多个 `init`：

```swift
class Person {
    var name: String
    var age: Int
    
    // 入口 A：默认无参构造器
    init() {
        self.name = "未命名"
        self.age = 0
    }
    
    // 入口 B：带参数的重载构造器
    init(name: String, age: Int) {
        self.name = name
        self.age = age
    }
}

// 💡 编译器根据你填写的参数标签，智能匹配执行哪台机器：
let someone = Person() // 匹配入口 A。someone 拥有 name = "未命名"
let manager = Person(name: "Cooper", age: 30) // 匹配入口 B。manager 拥有 name = "Cooper"
```

### 3.3 析构方法 `deinit` 的销毁监听

```swift
class Session {
    init() {
        print("会话开始")
    }
    
    // 💡 析构方法 (没有圆括号，不接受任何传参)
    deinit {
        print("会话结束，清理内存")
    }
}

func runDemo() {
    print("--- 步骤 1 ---")
    if true {
        let activeSession = Session() // 触发 init()，打印: 会话开始
        print("--- 步骤 2 ---")
    } // 出了 if 的大括号限制范围，activeSession 变量失去氧气死亡
      // 触发 deinit()，打印: 会话结束，清理内存
    print("--- 步骤 3 ---")
}
```

#### 🔍 语法细节解剖：
* **`deinit { ... }`**：
  * **`deinit` 关键字**。
  * **注意**：它不需要写小括号 `()`，因为它是在对象临死前由系统自动执行的，不接受外界传入任何参数。
* **出了大括号释放**：
  * `activeSession` 声明在 `if true { ... }` 的大括号内部。
  * 当代码走到第 141 行的右大括号 `}` 时，这个临时大括号的作用域（Scope）就彻底结束了。
  * 系统会立刻断开指向该对象的连线，引用计数归零，对象死亡，自动触发 `deinit`。最后打印出“会话结束”。
