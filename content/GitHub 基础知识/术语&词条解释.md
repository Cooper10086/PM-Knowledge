## 第一部分：电脑基础操作

### Terminal / 终端

把电脑想象成一家餐厅。平时你通过**图形界面（GUI）**点菜，就是看菜单、点图标；而**终端**就像直接走进厨房，用语言告诉厨师"给我炒一个蛋"。更直接、更快，但需要知道说什么。

- macOS：搜索 `Terminal` 打开
- Windows：搜索 `cmd` 或 `PowerShell`

---

### Command / 命令

在终端里输入的**一句话指令**，就叫 Command（命令）。就像对语音助手说"打开音乐"，只不过终端里要你自己打字，且必须拼对。

示例：`ls`（列出文件）、`cd Desktop`（进入桌面文件夹）、`mkdir myproject`（新建文件夹）

---

### CLI / 命令行界面

**Command Line Interface**，即只靠文字交互的操作方式。与之对应的是 **GUI（图形界面）**，比如点击图标、拖动窗口。CLI 就是：我打字  电脑响应。

- CLI 示例：`claude --help`
- GUI 示例：双击 Claude 图标

---

### Script / 脚本

把多条命令打包成一个文件，一次运行全部执行。就像**录制一段宏**——你把做早饭的步骤（烧水、放茶、等三分钟）写好，以后只需按一下就全自动。文件名通常叫 `setup.sh` 或 `install.sh`，运行方式：`bash setup.sh`

---

## 第二部分：代码与版本管理

### Git

安装在你电脑上的**"时间机器"软件**。每次修改代码，它帮你保存一个"存档点"（叫 commit）。出错了？一键回到任意历史版本。只在本地运行，不涉及互联网。

示例：`git init`  `git add .`  `git commit -m "修改了登录页"`

---

### GitHub

Git 存档的**云端仓库**，可以把你的代码同步上去。就像百度网盘是存文件的，GitHub 是存代码的，而且还能多人协作。全球最大的开源代码平台，AI 工具的安装包大多放在这里。

示例：`git push`（推送到 GitHub）、`git clone`（从 GitHub 下载项目）

---

### Package / 依赖包

别人写好的、可复用的功能模块。做饭不需要自己种菜，写代码也不用什么都自己写，直接安装别人的 package 调用就行。

示例：`npm install axios`（安装网络请求包）、`pip install openai`（安装 OpenAI 的包）

---

### npm / pip / brew / 包管理器

专门用来**下载和管理 package** 的工具。npm 用于 JavaScript，pip 用于 Python，brew 用于 macOS 软件。就像 App Store 之于 iPhone，但在终端里用命令操作。

示例：`brew install node`、`pip install requests`、`npm install react`

## 第三部分：AI / Agent 专属名词

### LLM / 大语言模型

**Large Language Model**，就是 ChatGPT、Claude、Gemini 背后的"大脑"。它通过海量文本学习，能够理解和生成自然语言。"大"指参数规模极大，"语言"是它的输入输出方式。

代表模型：GPT-4、Claude 3.5、Gemini 1.5

---

### Agent / 智能体

普通 AI 是"你问我答"；**Agent** 是"你给目标，它自己拆解步骤、调用工具、执行到完成"。就像你雇了一个**会自己决策的员工**，而不只是一个回答问题的机器。

示例：Claude Code 就是一个 Agent——你说"帮我写登录功能"，它自己建文件、写代码、运行测试。

---

### API / 接口

**Application Programming Interface**，让你的程序"打电话"给别人服务的方式。就像餐厅有对外的外卖窗口，你不用进厨房，通过窗口就能点餐。AI API 让你在自己产品里调用 GPT、Claude 的能力。

示例：向 `https://api.anthropic.com/v1/messages` 发送请求  拿到 Claude 的回复

---

### Prompt / 提示词

你发给 AI 的输入内容统称 **Prompt**。好的 Prompt 就像好的需求文档——说得越清晰，AI 输出越精准。"提示词工程（Prompt Engineering）"就是研究怎么把 Prompt 写好的学问。

常见分类：System Prompt（角色设定）、User Prompt（你说的话）、Few-shot（举例引导）

---

### Context Window / 上下文窗口

AI 在一次对话里能"记住"的内容范围，叫**上下文窗口**。超出这个范围，它就"忘"了。就像你的短期记忆：谈话越长，最早说的话越可能被"挤出去"。

示例：Claude 3.5 上下文窗口约 200K tokens，大约 15 万汉字

---

### Token / 词元

AI 处理文本的**最小计量单位**，不完全等于字或词。英文约 4 个字母 = 1 token；中文大约 1–2 个字 = 1 token。API 按 token 计费，上下文也按 token 计算容量。

示例："你好世界" ≈ 4 tokens；"Hello world" ≈ 2 tokens

---

### MCP / 模型上下文协议

**Model Context Protocol**，Anthropic 制定的标准，让 AI 能安全地连接外部工具（文件系统、数据库、第三方 App）。就像 **USB 接口的统一标准**——接口统一后，AI 就能"插上"任何工具。

示例：配置 MCP 后，Claude 可以直接读写本地文件、查 Jira、发 Slack 消息

---

### RAG / 检索增强生成

**Retrieval-Augmented Generation**：在 AI 回答之前，先去外部知识库搜索相关内容，再把搜到的内容一起发给 AI。就像开卷考试——AI 不需要全部记住，**可以先查资料再作答**。

适用场景：企业知识库问答、客服机器人

---

### Fine-tuning / 微调

在已有大模型基础上，用你的**专属数据再训练**，让它更符合你的业务风格。就像招来一个名校毕业生，再专门培训他"我们公司的说话方式"。成本比从头训练低得多。

示例：用 1000 条客服对话微调  AI 客服语气更像你们品牌

---

### Embedding / 向量化

把文字转换成一串数字（向量），使得**语义相近的词在数学上也更接近**。"猫"和"猫咪"的向量很近，"猫"和"飞机"的向量很远。RAG 和语义搜索都依赖 Embedding。

示例："我肚子饿了"和"我想吃东西" 向量相似度极高

---

### 本地部署 vs 云端

- **云端**：AI 跑在别人的服务器上，你通过网络调用（如 Claude.ai），开箱即用，按量计费。
- **本地部署**：把模型下载到自己的电脑/服务器上运行，数据不出门，适合有隐私要求的场景。代表工具：Ollama、LM Studio。

示例：`ollama run llama3`  在本地运行 Llama 3，完全离线

---

### Hallucination / 幻觉

AI **一本正经地编造事实**的现象。它不知道自己不知道，只是按概率生成"听起来正确"的内容。就像一个自信过头的人，不懂也要答。使用 AI 时，关键信息务必做人工核实。

示例：AI 编造不存在的论文、错误的法律条文、虚假的历史事件……都属于 hallucination
