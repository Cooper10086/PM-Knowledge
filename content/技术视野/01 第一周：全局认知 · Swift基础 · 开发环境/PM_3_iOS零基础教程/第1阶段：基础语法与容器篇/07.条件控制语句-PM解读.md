# 07. 条件控制语句 (iOS 基础教程 - PM 零基础精讲版)

> **本章学习目标**：掌握 Swift 流程控制的两大分流武器——`if` 逻辑判定和 `switch` 等值匹配，并理解 Swift 对状态安全要求极高的“完备性要求”。

---

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Control Flow** | “控制流走向” | **“逻辑分轨闸门”**。程序默认从上到下执行。通过条件语句，可以指挥程序在特定岔路口选择执行哪段代码。 |
| **if - else** | “用 if-else 分流” | **“二选一岔路”**。判断括号里的条件是否为 `true`。是就走左路，不是就走右路。 |
| **else if** | “多加几层 else if” | **“连续关卡检票口”**。从上到下一级一级检查，一旦发现某个检票口符合，执行完对应逻辑后立刻离开，不再看后面的关卡。 |
| **switch** | “这里换成 switch 匹配” | **“多轨火车分轨器”**。适合超过 3 个状态的精准匹配。比一长串 `else if` 更整齐、更清晰。 |
| **Exhaustiveness** | “必须覆盖全部状态” | **“全防漏兜底检查”**。Swift 的安全铁律。用 `switch` 匹配一个变量时，必须把所有可能性都写出来；如果漏掉一种，编译器直接报错拒绝运行。 |
| **default case** | “写个 default 保底” | **“备用收容箱”**。在 `switch` 中，如果所有的 case 条件都不符合，就会自动被塞进这个 default 箱子，防止程序因为没有匹配规则而发生卡死。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 `if` 与 `switch` 的选用原则
* **if 语句**：擅长处理“区间范围（如 $A > 10$）”或“复杂的混合条件（如 $A > 10$ 且 $B == \text{true}$）”。
* **switch 语句**：擅长处理“具体固定的值（如 $State == .connected$）”。

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

### 3.1 `if - else` 多分支语法

```swift
let outsideTemperature = 15

// 1. 单分支结构 (if)：符合条件就执行，不符合就假装没看见跳过
if outsideTemperature < 10 {
    print("天气寒冷")
}

// 2. 双分支结构 (if-else)：互斥逻辑，两条路必须且只能走一条
if outsideTemperature >= 28 {
    print("开启冷气")
} else {
    print("关闭冷气")
}
```

#### 🔍 语法符号解剖：
* **`if outsideTemperature < 10`**：
  * **大白话**：系统去查 `outsideTemperature` 箱子的值。如果 `15 < 10` 成立，就去执行大括号 `{}` 里的 `print`；因为不成立，所以大括号内的代码直接被忽略。
* **`else` 关键字**：
  * **大白话**：`else` 代表“否则 / 如果不满足上述所有条件”。

### 3.2 `switch` 的多值匹配与完备性法则

```swift
let itemCode = "B"

switch itemCode {
case "A":
    print("生鲜")
case "B", "C": // 1. 多值匹配：匹配到 B 或者 C 都会走到这里
    print("百货")
case "D":
    print("家电")
default: // 2. 强迫完备性：保底箱
    print("未知商品")
}
```

#### 🔍 语法细节解剖：
* **`switch itemCode`**：
  * **大白话**：开启分轨器，拿 `itemCode` 箱子里的具体字（如 `"B"`）去跟下面的各个 `case` 逐个比对。
* **`case "B", "C":`**：
  * 在 `case` 后面用逗号 `,` 连接多个值。
  * **大白话**：如果 `itemCode` 是 `"B"`，或者 `itemCode` 是 `"C"`，都会放行进入这一轨执行“百货”。
* **`default:`**：
  * **为什么不能省**：因为 `itemCode` 是个 String 字符串，世界上有无数种字符串。如果我们只匹配了 A, B, C, D，系统就会担心：“*如果变量是 E 怎么办？*” 为了防止出现代码盲区，Swift 强制要求最后写上 `default:`，用来兜底收容一切其他字符。

---

### 3.3 `switch` 搭配枚举 (Enum) 的免 default 特权

当 `switch` 遇到有限选项的枚举时，会发挥出极大的威力：

```swift
enum ConnectionStatus {
    case disconnected
    case connecting
    case connected
    case timeout
}

let currentStatus = ConnectionStatus.connected

// 💡 覆盖了枚举全部 4 个 Case，无需写 default 兜底！
switch currentStatus {
case .disconnected:
    print("已断开")
case .connecting:
    print("连接中")
case .connected:
    print("已连接")
case .timeout:
    print("超时")
}
```

#### 🔍 逐句解剖：
* **`switch currentStatus`**：
  * 因为 `currentStatus` 隶属于 `ConnectionStatus` 枚举门派。
  * 这个门派总共只有 4 个情况：`disconnected`, `connecting`, `connected`, `timeout`。
  * **大白话**：我们在下面写齐了 4 个 `case` 的轨道。因为可能性已经 100% 穷尽了，所以系统大发慈悲，**允许我们不写 default**。
  * **产品意义**：如果以后产品加了一个状态 `case block`（被拉黑），一旦研发漏改了某处的 switch，编译器在编译时就会报错：“*你漏掉了 block 状态的匹配！*” 逼着研发去补齐代码，绝对不会把带漏洞的包发给用户。
