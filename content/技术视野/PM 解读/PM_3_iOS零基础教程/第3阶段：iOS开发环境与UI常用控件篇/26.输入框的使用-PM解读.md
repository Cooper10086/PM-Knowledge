# 26. 单行输入框与键盘控制 (iOS 基础教程 - PM 零基础精讲版)

> **本章学习目标**：掌握 UITextField 单行输入框的核心属性（占位符、边框样式、内置清空小叉），学会使用两侧自定义悬挂槽（leftView/rightView），并掌握基于 Delegate 代理模式的键盘焦点收起及实时输入拦截校验逻辑。

---

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **`UITextField`** | “写个 TextField 输入框” | **“单行文字输入框”**。iOS 中用来接收用户单行打字输入（如账号、密码、搜索词）的标准控件。区别于多行输入的 UITextView。 |
| **First Responder** | “让它成为第一响应者” | **“抢过麦克风（获得焦点）”**。当前最活跃的物理响应窗口。哪个输入框调用了 `becomeFirstResponder()` 抢到了麦克风，软键盘就会**自动强制弹起**。 |
| **Resign Focus** | “让它 resign 失去第一响应者” | **“交还麦克风（收起键盘）”**。让输入框执行 `resignFirstResponder()`。输入框交还麦克风后，**软键盘就会自动退下收回**。 |
| **`leftView` / `rightView`** | “把小图标塞进 leftView” | **“输入框两侧的左右悬挂架”**。输入框内部两端预留的专属插槽，可以挂载搜索图标、密码明暗切换眼睛按钮、发送验证码按钮。 |
| **`UITextFieldDelegate`**| “挂载输入框的代理” | **“给输入框配一个安检传感器”**。输入框代理协议。输入框本身只管接收打字。配了代理后，每次用户打字、清除、按回车，都会向代理（ViewController）发出通知进行实时检查。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 为什么设置了 leftView，界面上却不显示？
有些研发在代码里写了 `usernameField.leftView = UIImageView(...)`，运行却发现输入框左侧光秃秃的，什么也没有。
* **原因**：因为系统默认的 `leftViewMode` 是 `.never`（从不显示）。
* **解决方案**：必须在代码里显式写上一句 **`usernameField.leftViewMode = .always`**，强行把侧面挂架的展示开关打开。

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

### 3.1 创建并配置输入框外观

```swift
let usernameField = UITextField(frame: CGRect(x: 30, y: 100, width: 300, height: 40))

// 1. 设置边框类型 (UITextField.BorderStyle)。如果不写，默认是 .none（看不见边框！）
usernameField.borderStyle = .roundedRect // .roundedRect 是浅灰色圆角边框

// 2. 占位提示语 (Placeholder)
usernameField.placeholder = "请输入手机号/邮箱"

// 3. 一键清空小叉按钮 (clearButtonMode)
// .whileEditing 代表只有在输入框处于编辑状态且里面有字时，右侧才亮起小叉，方便用户一键清除
usernameField.clearButtonMode = .whileEditing

// 4. 挂载左侧账号小图标
let userIcon = UIImageView(image: UIImage(named: "icon_user"))
userIcon.frame = CGRect(x: 0, y: 0, width: 30, height: 30)
userIcon.contentMode = .center
usernameField.leftView = userIcon
usernameField.leftViewMode = .always // 🚨 开启左侧挂载架开关！

self.view.addSubview(usernameField)
```

### 3.2 绑定代理与生命周期拦截 (Keyboard & Input Validation)

软键盘的回车收起，以及输入的字数限制，都必须通过代理协议进行实时拦截：

```swift
import UIKit

// 声明页面遵守 UITextFieldDelegate 协议（宣称自己有资格充当安检员）
class LoginViewController: UIViewController, UITextFieldDelegate {
    
    private let passwordField = UITextField()
    
    override func viewDidLoad() {
        super.viewDidLoad()
        
        passwordField.frame = CGRect(x: 30, y: 160, width: 300, height: 40)
        passwordField.borderStyle = .roundedRect
        passwordField.placeholder = "请输入密码"
        passwordField.isSecureTextEntry = true // 💡 密码安全框：打字自动显示为黑色实心圆点
        
        // 🚨 核心：将 passwordField 的安检感应线，接在自己 (self) 身上！
        passwordField.delegate = self
        
        self.view.addSubview(passwordField)
    }
    
    // MARK: - UITextFieldDelegate 协议回调方法 (安检方法)
    
    // 💡 拦截一：用户点击软键盘右下角的 “确定 / 完成 / 回车” 键时触发
    func textFieldShouldReturn(_ textField: UITextField) -> Bool {
        // 命令输入框交还麦克风，软键盘就会自动退下去！
        textField.resignFirstResponder() 
        return true
    }
    
    // 💡 拦截二：用户每按下一个字母，还没写进框里的前一刹那触发
    func textField(_ textField: UITextField, shouldChangeCharactersIn range: NSRange, replacementString string: String) -> Bool {
        // replacementString 是用户刚刚敲下的字符。
        // 如果我们返回 false，这个敲下的字符就会直接作废写不进输入框。
        print("用户打的字是: \(string)")
        return true 
    }
}
```

#### 🔍 语法细节解剖：
* **`passwordField.isSecureTextEntry = true`**：
  * **`isSecureTextEntry`** 属性。
  * **大白话**：设为真。输入框会自动转为保密的密文圆点模式。
* **`passwordField.delegate = self`**：
  * **大白话**：接通安检线。把输入框的警报接收端设为当前的 `LoginViewController`（即 `self`）。如果不写这一句，下面的 `textFieldShouldReturn` 等回调方法**终生不会被触发**。
* **`textField.resignFirstResponder()`**：
  * **大白话**：把第一响应者焦点卸载掉，软键盘自动退下。
* **`shouldChangeCharactersIn` 里的 `return true`**：
  * **注意**：如果返回 `false`，用户的按键输入会被系统废弃（比如写只读验证码框，或者输入长度超标时，研发会在这里截断并返回 `false`）。
