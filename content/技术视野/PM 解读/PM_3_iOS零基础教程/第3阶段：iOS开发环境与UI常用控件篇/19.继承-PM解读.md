> **本章学习目标**：掌握面向对象（OOP）三大核心法宝：封装（隔离危险属性）、继承（少写重复代码的冒号语法）、多态（父类容器装子类对象实现“千人千面”）。

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Encapsulation** | “做个封装” | **“隐私隔离”**。把类的某些敏感特征锁死在 private 抽屉里，只留安全的公开方法供外部读取，确保内部数据健康。 |
| **Inheritance** | “继承这个类” | **“套用家族模板（冒号语法 `:`）”**。子类（派生类）可以自动免费拥有父类（基类）里所有非私有的属性和方法。 |
| **Superclass / Subclass**| “父类与子类” | **“家族模板与个性改进版”**。父类提供基础通用规范，子类在此基础上添加自己特有的属性或功能。 |
| **Override** | “重写父类的方法” | **“新规重写”**。使用 `override` 关键字。子类嫌弃父类的某个方法太土或不符合当前业务，在子类里强行换上自己定制的代码。 |
| **`super.`** | “先调一下 super” | **“请老祖宗先显灵”**。子类重写方法时，如果不想彻底抛弃父类的原生逻辑，可以用 `super.方法()` 让父类先跑一遍，再追加自己的新逻辑。 |
| **Polymorphism** | “利用多态实现” | **“以大统小 / 动态多面手”**。父类变量（容器）里，装载着不同的子类实例。在运行的那一刻，系统会根据盒子里到底是谁，自动执行谁重写的方法。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 继承关系下的“私有成员继承局限”
* **教程说**：`Teacher` 继承自 `Person`，但无法直接读写父类的 `private var age` 属性。
* **大白话翻译**：虽然子类不能用 `self.age` 去改写它，但请注意，`age` 这个箱子其实**隐式存在于子类的堆内存中**。当你调用从父类继承来的 `play()` 时，这个方法依然能读取并打印出这个私有变量。它只是被藏起来了，没有消失。

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

### 3.1 继承下的“两阶段初始化”顺序（安全准则）

```swift
class Person {
    var name: String = "未命名"
}

class Teacher: Person {
    var school: String
    
    // 重写父类的默认无参构造器
    override init() {
        self.school = "希望小学" // 💡 第一阶段：先初始化自己独有的属性！
        
        super.init()           // 💡 第二阶段：调用父类构造器完成继承的初始化
    }
}
```

#### 🔍 语法细节解剖：
* **`class Teacher: Person`**：
  * 冒号 `:` 语法。
  * **大白话**：声明 `Teacher` 继承自 `Person`（`Teacher` 是子类，`Person` 是父类）。
* **`super.init()`**：
  * **大白话**：`super` 意为“上级/父辈”。通知父类的初始化构造器运行。
  * **为什么不能调换顺序**：Swift 规定：必须“先己后人”。必须先把子类自己声明的 `school` 箱子装满，才能执行 `super.init()` 去初始化父类的 `name` 等继承来的变量。如果把 `super.init()` 写在最前面，编译器会报红线拒绝编译。

### 3.2 方法重写与 `super.` 扩展

```swift
class Teacher: Person {
    // 重写父类的 play() 方法
    override func play() {
        super.play() // 💡 敬茶：先去执行一遍父类 play() 里的打印逻辑
        print("备课是我的日常休闲") // 💡 追加：写下我子类特有的动作
    }
}
```

### 3.3 运行时多态 (Polymorphism) 机制

```swift
class Animal {
    func makeNoise() { print("叫声") }
}
class Dog: Animal {
    override func makeNoise() { print("🐶 汪！") }
}
class Cat: Animal {
    override func makeNoise() { print("🐱 喵～") }
}

// 1. 声明一个父类 Animal 类型的容器变量 pet
var pet: Animal

// 2. 往 pet 箱子里塞入 Dog 实例，执行 makeNoise
pet = Dog()
pet.makeNoise() // 输出: 🐶 汪！

// 3. 往同一个 pet 箱子里塞入 Cat 实例，执行 makeNoise
pet = Cat()
pet.makeNoise() // 输出: 🐱 喵～
```

#### 🔍 语法细节解剖：
* **`var pet: Animal`**：
  * **大白话**：声明一个挂着 `Animal` 标签的箱子。
  * **多态的魔力**：因为 `Dog` 和 `Cat` 都是 `Animal` 的子类（后代）。所以这个箱子**既可以装 Dog，也可以装 Cat**。
  * 当我们对 `pet` 喊“叫一下（`pet.makeNoise()`）”时，电脑会看一眼现在盒子里装的到底是谁：如果是狗，就去执行狗重写的“汪”；如果是猫，就执行“喵”。发号施令的代码不需要关心对方具体是猫是狗，只管下达 `makeNoise()` 即可。
