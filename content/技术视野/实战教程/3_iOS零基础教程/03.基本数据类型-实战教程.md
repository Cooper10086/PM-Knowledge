# 03.基本数据类型-实战教程

在 Swift 的强类型系统设计中，每一个常量或变量在编译期都必须具有确定的“数据类型”。数据类型规定了对应的“箱子”（内存空间）可以安全存放的内容规范，避免在运行时发生意料之外的类型混乱。

本教程系统整理并深入解析 Swift 中最基础、最核心的数据类型及其底层机理，助力零基础开发者快速建立严密的技术知识体系。

---

## 🛠️ Swift 基础类型核心速查表

| 数据类型名称 | 关键字 | 位数 (64位设备) | 字节大小 | 典型取值范围 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **有符号整型** | `Int` | 64-bit | 8 Bytes | $-2^{63} \sim 2^{63}-1$ | 常规计数、索引、大多数整型场景 |
| **8位有符号整型** | `Int8` | 8-bit | 1 Byte | $-128 \sim 127$ | 年龄、极小范围的常规计数（内存优化型） |
| **8位无符号整型** | `UInt8` | 8-bit | 1 Byte | $0 \sim 255$ | 图像像素值（如RGB）、年龄、只可能为正的值 |
| **单精度浮点数** | `Float` | 32-bit | 4 Bytes | 精确到小数点后 6 位 | 对内存要求极高且精度要求有限的小数场景 |
| **双精度浮点数** | `Double` | 64-bit | 8 Bytes | 精确到小数点后 15 位 | 坐标、高度、物理计算（苹果推荐的默认浮点数） |
| **布尔型** | `Bool` | 8-bit (编译期) | 1 Byte | `true` 或 `false` | 控制流判断、UI开关激活状态、条件分支控制 |

## 📘 深入解析 Swift 整型系统与存储机制

### 1. 位数（Bit）与字节（Byte）的底层换算
计算机内部通过最小的存储单元——**位 (Bit)** 来记录二进制数字 `0` 或 `1`。
- **换算公式**：$1 \text{ Byte（字节）} = 8 \text{ Bits（比特位）}$
- **内存换算关系**：
  $$1 \text{ TB} = 1024 \text{ GB} \quad\Rightarrow\quad 1 \text{ GB} = 1024 \text{ MB} \quad\Rightarrow\quad 1 \text{ MB} = 1024 \text{ KB} \quad\Rightarrow\quad 1 \text{ KB} = 1024 \text{ B}$$

### 2. Int8 类型的范围推导
`Int8` 占用 1 个字节（8 位）。系统将其二进制表示中的第一位规定为**符号位**（`0` 代表正数或零，`1` 代表负数），从而得出其十进制的取值范围为 $-128$ 到 $127$：
- 正数区间（符号位为0）：最小为 `00000000` (十进制0)，最大为 `01111111` (十进制127)；
- 负数区间（符号位为1）：通过补码表示，最小可表示至 `-128`。

### 3. 如何通过代码查看类型的范围极限
在日常开发中，无需死记硬背各类型极值，Swift 允许直接通过属性访问极值：
```swift
print("Int8 最小值: \(Int8.min)") // 输出: -128
print("Int8 最大值: \(Int8.max)") // 输出: 127

print("UInt8 最小值: \(UInt8.min)") // 输出: 0
print("UInt8 最大值: \(UInt8.max)") // 输出: 255
```

### 4. 溢出崩溃 (Overflow) 警示
如果程序试图将超出类型表示范围的值赋给该变量，Swift 编译器或运行时将会直接报错并导致程序崩溃。这种“编译期拦截与运行时中断”是 Swift 旨在打造“类型安全语言”的体现。
```swift
// ⚠️ 下面代码会导致编译期报错:
// "Integer literal 200 overflows when stored into 'Int8'"
var age: Int8 = 200 
```

### 5. 动态长度的默认类型 `Int`
在 Swift 中，直接使用 `Int` 关键字，其具体的所占位数并非完全固定，而是与**目标设备的处理器架构位数**相契合：
- **32 位架构机器**上：`Int` 自动映射为 `Int32`
- **64 位架构机器**上：`Int` 自动映射为 `Int64`

由于现代苹果产品（iPhone、iPad、Mac 等）均采用 64 位架构，因此在当前开发中，`Int` 与 `Int64` 完全等价。

## 🎨 显式标注与自动推断的工程实践

### 1. 显式类型标注（Explicit Type Annotation）
在声明常量或变量时，在名称后方加上 `:`，并明确标出具体类型名称。
```swift
// 显式声明整型变量
var userScore: Int = 100

// 显式声明浮点数常量
let piValue: Double = 3.14159
```

> 💡 **官方推荐代码格式规范**：
> 变量名与冒号之间不保留空格，冒号与数据类型之间必须保留一个空格，等号两边需各保留一个空格。
> 格式规范：`var 变量名: 类型 = 初始值`

### 2. 隐式类型推断（Implicit Type Inference）
如果不为常量或变量指定具体的数据类型，Swift 编译器会依据赋值符号右侧的字面值（Literal Value）自动推断并设定其类型：
```swift
var count = 100        // 系统自动推断为 Int
let average = 87.5     // 系统自动推断为 Double (注意：Swift 浮点数字面值默认推断为 Double，而非 Float)
var isCompleted = true // 系统自动推断为 Bool
```

### 3. 工程建议：什么时候该写显式标注？
在大型项目的团队协作中，虽然类型推断能减少冗长代码，但**显式类型标注有利于提升代码的清晰度和可读性**。当变量数量庞大、作用域较广时，清晰的类型标注可以防止阅读者在复杂的调用链路中混淆类型，同时还能提升 Swift 编译器的编译速度。

## 🔬 浮点数与精度选择 (Float vs Double)

- `Float` 占用 32-bit (4 字节) 的内存空间，精度可保留至小数点后 6 位。
- `Double` 占用 64-bit (8 字节) 的内存空间，精度可保留至小数点后 15 位。

```swift
// 显式声明 Float 类型
var floatValue: Float = 2.333333333333

// 显式声明 Double 类型
var doubleValue: Double = 2.333333333333

print("Float 输出: \(floatValue)")   // 精确度衰减，只保留前几位
print("Double 输出: \(doubleValue)") // 精确地显示小数点后更长范围
```

> 📌 **开发建议**：在对精度要求敏感的科学计算、物理模型计算或经纬度坐标系统中，请始终使用 `Double`。由于 `Double` 精确度极佳，在 iOS 的 SDK 中（如 CoreGraphics 等框架），默认使用的几乎都是 `Double`。

## 🎛️ 布尔型 (Bool) 的开关逻辑控制

布尔值 `Bool` 只有两个合法的状态值：`true` (真) 与 `false` (假)。由于状态非常专一，在实现系统的开关控制时非常节省内存资源。

在后续实战开发中，通常用它来绑定用户界面的开关控制或做条件流分支：
```swift
// 声明一个描述开关状态的变量
var isBluetoothOn: Bool = false

// 当开启蓝牙时，将状态设置为 true
isBluetoothOn = true

if isBluetoothOn {
    print("蓝牙已开启，可以进行设备扫描。")
} else {
    print("蓝牙处于关闭状态。")
}
```
