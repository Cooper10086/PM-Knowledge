> **本章学习目标**：看懂 Swift 函数的基本语法结构，理解“声明（图纸）”与“调用（开动机器）”的物理生命周期区别，并学会为您的卡牌游戏发牌按钮（Deal）封装业务逻辑函数。

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Function** | “把这段代码包成函数” | **“封装好的加工机器”**。把多行完成特定动作的代码打包，起个动作名字。外部直接呼叫名字，即可一键执行内部所有指令，避免重复写长代码。 |
| **Declaration** | “函数的声明定义” | **“画出机器设计图纸”**。用 `func` 关键字规划好这台机器叫什么、接收什么原料、具体干什么。**声明时机器并不会运转**。 |
| **Calling** | “调用这个方法/函数” | **“拍下机器启动按钮”**。写出 `函数名()` 的代码动作。只有被调用时，系统才会寻址并开动机器，顺序跑完大括号里的代码。 |
| **Parameters** | “入参列表” | **“机器外面的入料槽”**。写在圆括号 `()` 里。用来规定外界在启动我这台机器时，必须往里面塞什么规格的数据供我运算。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 为什么我们需要“函数”？——以 Deal 发牌按钮为例
当玩家点击界面上的“Deal”按钮时，后台实际上在一瞬间干了这 5 件事：
1. 生成玩家卡牌的随机数字（如 3）。
2. 生成电脑卡牌的随机数字（如 11）。
3. 用数字拼接成图片名（`"card3"`、`"card11"`），并让 UI 界面把卡牌换成对应的图。
4. 判定谁大谁小（3 < 11，电脑赢）。
5. 胜者的分数累加 1 分，并在界面上重绘渲染新分数。

如果这 5 行复杂的逻辑代码直接塞在按钮点击事件的大括号里，代码会显得极为臃肿，后续如果添加“音效”、“动画”逻辑，修改难度极大。
* **PM 解决思路**：我们画一张机器图纸 `func deal() { 5件事的逻辑 }` 封装起来。
* 在按钮点击的地方，**我们只需写一行 `deal()` 呼叫它即可**，界面看起来清爽且极易排查 Bug。

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

请看 Playground 中关于函数声明与调用的代码解剖：

```swift
import UIKit

// ==================== 1. 函数声明阶段 (画设计图，不执行) ====================
// 💡 定义一个叫 displayWelcomeMessage 的机器
func displayWelcomeMessage() {
    print("-------------------------")
    print(" 欢迎进入 War Card Game ")
    print("-------------------------")
}

func logTurnStart() {
    print("[系统通知] 新回合开始，准备发牌...")
}

// ---- 🚨 此时点击运行，控制台一片空白。因为只画了图纸，尚未启动机器 ----

// ==================== 2. 函数调用阶段 (按下按钮，启动机器) ====================
displayWelcomeMessage() // 💡 机器一号开动！控制台打印出 3 行横杠欢迎文案
logTurnStart()          // 💡 机器二号开动！控制台打印出系统通知

print("玩家点击了 Deal 按钮") // 主流程代码顺序执行

// 3. 复用性体现：不需要重复写打印通知那句话，直接再次呼叫名字即可启动
logTurnStart()          // 💡 机器二号再次开动！控制台打印出系统通知
```

* 当我们调用一次 `deal()`，上面的 3 个步骤就会按顺序秒级跑完，卡牌变了，分数也加了，完美的事件驱动达成！
