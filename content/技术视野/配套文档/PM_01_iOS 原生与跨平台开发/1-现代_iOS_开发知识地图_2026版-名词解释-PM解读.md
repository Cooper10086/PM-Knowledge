# 1-现代_iOS_开发知识地图_2026版-名词解释 (iOS配套文档 - PM 零基础精讲版)

> **本章学习目标**：看懂 iOS 开发生态中所有核心的高频技术名词，理解每个名词对应的真实开发动作，消除与研发的沟通壁垒。

---

## 📖 1. 本章名词字典 (Glossary for PM)

### 💻 第一篇：开发环境

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **macOS** | “苹果系统” | **“开发大底座”**。iOS 研发必备的苹果桌面系统，因为苹果官方开发工具 Xcode 只能在这个系统里运行。 |
| **Terminal** | “打开终端敲命令” | **“无界面的操作黑窗口”**。省去点击鼠标图标，直接通过打字下命令来操控电脑的“纯文字暗道”。 |
| **Shell** | “换成 zsh” | **“黑窗口里的翻译官”**。负责把你输入终端的每一行英文命令，翻译给电脑硬件执行并把结果打印出来。 |
| **Homebrew** | “用 brew 装一下” | **“命令行的软件应用商店”**。通过简单打字下命令，自动联网帮你下载、安装、配置各种开发工具的管家。 |

### 📂 第二篇：版本控制与协同

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Git** | “先提交个 commit” | **“代码时光机”**。记录每一次代码修改历史，支持多人协同开发，并能随时退回到过去的某个版本。 |
| **GitHub** | “代码提交到 GitHub” | **“云端代码托管平台”**。备份代码、团队协作和进行代码评审（Code Review）的公共云端平台。 |
| **SSH** | “配置个 SSH 密钥” | **“免密码加密安全通道”**。通过生成一对公私钥，让你的电脑免账号密码直接与 GitHub 等平台安全通信。 |
| **Branch** | “拉个新分支开发” | **“平行宇宙”**。从主线上拉出来的一条独立开发线。在新分支上修改、试错不影响正在线上运行的稳定代码。 |
| **Merge** | “把分支合并进来” | **“时空融合”**。将新分支上开发测试好的功能，安全合并回主线代码的操作。 |
| **Pull Request (PR)** | “提个 PR 帮我 Review” | **“合并申请单”**。在 GitHub 上向团队提出申请，将你的分支合并到主线中，并提供差异比对供团队评审。 |

### 🛠 第三篇：Swift 编程语言

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Swift** | “用 Swift 开发” | **“苹果现代官方语言”**。苹果 2014 年推出的现代化编程语言，安全、快速，全面取代了老旧的 Objective-C。 |
| **Optional** | “这个值是可选的，要解包”| **“薛定谔的属性盒子”**。值可能有，也可能为 nil。Swift 强行要求必须先安全拆开盒子判断有无，彻底杜绝了因空数据导致的 App 闪退。 |
| **Struct** | “用结构体做数据模型” | **“一次性卡牌模板（值类型）”**。分发或赋值时是“直接印一份新拷贝”，修改拷贝不会影响原来的卡牌。 |
| **Class** | “用类做 ViewModel” | **“共享白板（引用类型）”**。分发时是“共享同一个白板的地址”，任何人在上面修改，其他人看到的都跟着变。 |
| **Protocol** | “遵循这个协议” | **“岗位说明规范 / 契约”**。规定好遵循它的人必须实现哪些功能和方法（比如必须能“发声”），不管你是人还是机器。 |
| **Concurrency** | “写个 async/await 异步” | **“一心二用（并发）”**。让程序在后台默默下载数据，同时前台依然流畅响应用户点按和滚动的多线程技术。 |

### 🎨 第四篇：UI 开发框架与架构

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **SwiftUI** | “用 SwiftUI 写界面” | **“画设计草图式的声明式 UI”**。你只要写大白话告诉系统界面要长什么样，系统自动渲染并在数据变动时自动刷屏。 |
| **UIKit** | “这个地方得用 UIKit” | **“一砖一瓦搭建的命令式 UI”**。老一代框架。需要研发自己用代码创建每一个按钮、设置坐标，并手动编写刷屏逻辑。 |
| **MVVM** | “用 MVVM 架构” | **“三权分立架构”**。Model（纯数据模型）、View（画皮界面）、ViewModel（精干的业务管家）。管家从网络拿数据加工后通知界面刷新。 |
| **Navigation** | “做页面导航跳转” | **“App 页面公交栈”**。管理界面之间“点按进入”和“左滑返回”的层级路标。 |
| **State** | “把这个变量标记为 State”| **“UI 自动刷新的开关”**。只要状态数据一发生修改，绑定它的界面瞬间自动跟着重绘渲染。 |

### 📦 第五篇：Xcode 工程管理

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **Xcode** | “打开 Xcode” | **“iOS 研发官方总操盘软件”**。苹果唯一的官方集成开发环境，包含写代码、画界面、编译、测试、上架一条龙功能。 |
| **Project** | “打开工程文件” | **“单个应用档案盒”**。以 `.xcodeproj` 结尾，包含你这个 App 项目的所有代码、图片和编译配置。 |
| **Workspace** | “必须打开 Workspace” | **“多个档案盒的大架子”**。以 `.xcworkspace` 结尾，可以把你的 App 工程和所有第三方依赖工程框在同一个窗口协作。 |
| **Target** | “这是个新的 Target” | **“最终出厂产物”**。比如一个工程里有“主App”、“今日桌面插件”和“测试包”三个产物，每个产物就是一个 Target。 |
| **Scheme** | “切换到编译 Scheme” | **“生产流水线指令集”**。告诉 Xcode 点击编译时是要做“开发版调试”还是“正式版打包”。 |
| **Build** | “Build 一下” | **“编译加工”**。把人类看得懂的 Swift 英文代码编译打包成手机能跑的机器码（二进制文件）的过程。 |
| **Archive** | “打个 Archive 包” | **“打包封装，准备出厂”**。在正式发布模式下对 App 进行极限优化编译，打包成用于上传应用商店的封箱包。 |

### 🌐 第六篇：网络与本地数据存储

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **URLSession** | “用 URLSession 发请求”| **“苹果官方网络通信邮差”**。iOS 自带的联网功能，用来发 HTTP 请求、下载文件或上传数据。 |
| **REST API** | “调这个 REST 接口” | **“标准网络办事窗口”**。遵循 HTTP 规范，用 GET、POST、DELETE 等标准动作来增删改查数据的接口设计。 |
| **JSON** | “返回一个 JSON” | **“世界通用的文本数据格式”**。以大括号和冒号排布的纯文本，手机和服务器都能轻松看懂并解析。 |
| **Codable** | “让这个模型遵循 Codable”| **“全自动中泰翻译官”**。Swift 自带协议，只要挂上它，JSON 文本和 Swift 类之间只需一行命令就能互换。 |
| **Core Data** | “本地数据库用 Core Data”| **“老牌关系型本地数据库”**。存储本地数据，功能强大但配置复杂，样板代码极多。 |
| **SwiftData** | “用新出的 SwiftData” | **“超轻量现代本地数据柜”**。iOS 17 推出，直接用 Swift 语法在代码里存数据，免去了画表配置的折磨。 |

### 🏗 第七篇：依赖管理与工程化

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **SPM** | “直接用 SPM 引入依赖” | **“Xcode 内置的软件管家”**。无需装外部工具，直接在 Xcode 网页里填 GitHub 链接就能下载开源第三方库。 |
| **CocoaPods** | “跑个 pod install” | **“老牌的 iOS 第三方库市场”**。iOS 开发中最著名的外部依赖管理软件，通过一个叫 Podfile 的清单来管第三方库。 |
| **Ruby** | “Mac 上的 Ruby 坏了” | **“iOS 自动化脚本的幕后语言”**。CocoaPods、Fastlane 都是用 Ruby 语言写的，所以 Mac 开发机必须装 Ruby 才能跑这些自动化指令。 |
| **Bundler** | “用 bundle exec 执行” | **“Ruby 脚本的版本锁”**。锁定 CocoaPods 或 Fastlane 的版本，确保团队里每个人电脑上的自动化打包工具版本一致，防编译报错。 |
| **Fastlane** | “用 fastlane 打包” | **“iOS 一键打包发布指挥官”**。用脚本代替人在 Xcode 里点按各种按钮，一键同步证书、打包、上传应用商店。 |

### 🔄 第八篇：CI/CD 持续集成与分发

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **GitHub Actions** | “用 Actions 自动跑测试” | **“云端的全自动打包机器人”**。代码一提交，云端虚拟机立刻把代码拉下来编译、测试、甚至自动打包发版。 |
| **Xcode Cloud** | “配个 Xcode Cloud” | **“苹果官方的云端打包机”**。深度整合在 Xcode 里的 CI/CD 工具，在苹果云端服务器上帮我们跑测试和自动发包。 |
| **Bitrise** | “在 Bitrise 上配流水线” | **“可视化拖拽打包平台”**。面向移动开发的打包平台，像搭积木一样拖拽就能连出一条打包分发链。 |
| **Jenkins** | “用 Jenkins 打包” | **“机房自建的打包大管家”**。开源免费的自建打包平台，适合买一台 Mac mini 放在公司里给全部开发自动打包。 |
| **GitLab CI** | “配个 GitLab Runner” | **“GitLab 自带的流水线”**。需要你找台 Mac 电脑装上 GitLab Runner 程序，代码提交后，这台 Mac 就会被唤醒开始编译。 |

### 🚀 第九篇：测试与证书签名上架

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **TestFlight** | “把包传到 TF 测一下” | **“苹果官方内测沙盒商店”**。用于在 App 正式上架前，给公司内部或外部受邀用户下载测试测试包的专用 App。 |
| **App Store Connect**| “在后台新建个版本” | **“苹果应用上架管理后台网站”**。开发者填入 App 商品信息、隐私政策、上传测试包、提交苹果审核的官方唯一门户。 |
| **Code Signing** | “签名报错了” | **“防篡改数字加密防伪戳”**。打包的最后一步，用开发者私钥进行加密，证明该 App 是合法开发者出品且没被黑客改过。 |
| **Certificates** | “申请个发布证书” | **“苹果官方数字身份证”**。证明你的开发者身份，双击导入电脑钥匙串，没有证书就无法完成签名和打包。 |
| **Provisioning Profile**| “更新描述文件” | **“苹果特有的全家福通信证”**。把“证书+AppID+能运行的手机ID列表+核心权限”打包在一起的描述文件，四者核对无误手机才放行运行。 |
