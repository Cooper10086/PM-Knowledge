# 20. 结构体与协议 (iOS 基础教程 - PM 零基础精讲版)

> **本章学习目标**：看懂 Swift 值类型结构体 `struct` 的深拷贝物理行为，掌握协议 `protocol`（契约规范）的设计，并学会看懂 iOS 开发最经典的通信模式——“委托代理模式 (Delegation)”。

---

## 📖 1. 本章名词字典 (Glossary for PM)

| 英文技术名词 | 研发口头禅 | 大白话通俗解释 (PM Metaphor) |
| :--- | :--- | :--- |
| **`struct`** | “写个结构体” | **“无碳复写复印单”**。结构体。创建出来的值在传递时进行**深拷贝**：每次都复制一整份独立的全新实体。修改副本，原件毫无变化。没有内存泄漏风险。 |
| **`protocol`** | “定义个协议契约” | **“国家强制性标准规格书”**。里面只写属性和方法的名字，不写任何具体实现代码。任何类型只要签了它，必须在自己大括号里实现它规定的所有功能。 |
| **Conform** | “遵守/实现这个协议” | **“签署协议书并保证按规办事”**。类或结构体声明遵守协议，并在自己内部把协议规定好的方法补齐代码实现。 |
| **Delegation** | “写个 Delegate 代理回调” | **“老板（主页面）与秘书（子页面）”**。一种经典的设计模式。子页面编辑完数据后，根据协议拨通老板的代理人电话，将数据安全反向传递回去。 |

## 🧭 2. 教程步骤逐步拆解 (Step-by-Step Breakdown)

### 2.1 继承与多协议采纳的“排队规则”
* **教程说**：`class WirelessMouse: BaseDevice, USBDevice, Chargeable`
* **大白话翻译**：在 Swift 中，一个类只允许有**一个亲爸爸（单继承）**，但可以**签署多份工作协议（多协议采纳）**。
* **排队规定**：写代码声明时，**亲爸爸（父类名）必须雷打不动排在冒号后面的第一位**，后面用逗号拼上各个协议的名字。位置写错了，编译器会报错。

## 💻 3. 代码逐句大白话解剖 (Line-by-Line Code Breakdown)

### 3.1 结构体 `struct` 与 类 `class` 的拷贝行为对比

```swift
class ClassPerson { var name: String = "小王" } // 类（引用类型）
struct StructPerson { var name: String = "小王" } // 结构体（值类型）

// 1. 类测试 (浅拷贝-共享链接)
let cp1 = ClassPerson()
let cp2 = cp1
cp2.name = "小红"
print(cp1.name) // 输出: 小红 (cp1 的 name 跟着变了！)

// 2. 结构体测试 (深拷贝-完整克隆)
var sp1 = StructPerson()
var sp2 = sp1
sp2.name = "小红"
print(sp1.name) // 输出: 小王 (sp1 保持独立，不受 sp2 修改的影响)
```

### 3.2 声明并遵守协议 (Protocol)

```swift
// 1. 定义标准 USB 设备规格协议
protocol USBDevice {
    func connect()      // 规定必须有连接功能
    func transferData() // 规定必须有数据传输功能
}

// 2. 鼠标类声明遵守该协议
class Mouse: USBDevice {
    func connect() {
        print("鼠标已连接") // 💡 补齐代码实现
    }
    
    func transferData() {
        print("发送光标位移") // 💡 补齐代码实现
    }
}
```

### 3.3 经典实战：委托代理模式 (Delegation) 页面反向传值

```swift
// 步骤一：定义代理契约（写清楚：秘书干完活，必须向老板汇报什么）
protocol EditViewDelegate: AnyObject {
    func didFinishEditing(text: String)
}

// 步骤二：子页面 B (秘书)
class DetailViewController {
    // 声明 delegate 变量，类型是上面的协议。
    // weak 意为“弱引用”，用来防止秘书和老板互相拉着不放导致内存泄露
    weak var delegate: EditViewDelegate?
    
    func userClickedSave(content: String) {
        // 用户点保存，秘书打电话向老板汇报，并把 content 传过去
        delegate?.didFinishEditing(text: content)
    }
}

// 步骤三：主页面 A (老板) - 声明遵守协议
class HomeViewController: EditViewDelegate {
    func showDetailPage() {
        let detailVC = DetailViewController()
        detailVC.delegate = self // 💡 老板把自己 (self) 设为秘书的代理接收人
    }
    
    // 步骤四：老板实现协议方法，接收回传的值
    func didFinishEditing(text: String) {
        print("老板拿到了修改后的文字: \(text)")
    }
}
```

#### 🔍 逐句解剖：
* **`weak var delegate: EditViewDelegate?`**：
  * **`weak` 关键字**：非常重要。告诉系统，这是一个“弱引用”连线。
  * **大白话**：老板开门放秘书出去，如果两边都是死死抓牢（强引用），当页面关闭时，两个大对象在内存里互相拉拉扯扯，ARC 无法回收，就会产生**内存泄漏**。用 `weak` 可以实现页面关闭时，连线自动温柔断开。
* **`delegate?.didFinishEditing(text: content)`**：
  * **问号 `?` 作用**：因为 `delegate` 声明为了可选值（可能会是 nil，即可能没有老板认领它）。
  * **大白话**：如果有老板认领我（`delegate` 非空），就去调用老板的 `didFinishEditing` 方法把文字传给老板；如果没有老板认领我，这一句直接被安全跳过，绝不报错。
