# 07.条件控制语句-实战教程

在 Swift 中，**条件控制语句**负责管理代码的控制流走向。通过对布尔条件的评估，控制流得以在不同分支间切换，实现逻辑判断和业务分流。

本教程将全面解析 Swift 流程控制的两大支柱：`if` 分支与 `switch` 分支，并着重阐述它们的设计差异与实战工程规范。

---

## ⚖️ if 语句与 switch 语句对比表

| 对比维度 | `if` 语句 | `switch` 语句 |
| :--- | :--- | :--- |
| **条件类型** | 判断区间范围、关系表达式、复杂逻辑组合（`&&`, `||`） | 匹配具体的单一固定值、特定元组或枚举模式 |
| **返回值类型** | 条件表达式必须计算出 `Bool` 结果 | 匹配的值可以是任意支持模式匹配的类型（Int, String, Enum 等） |
| **完备性要求** | 非强求（可单独使用 `if`，无 `else`） | **强求完备性（Exhaustiveness）**，必须覆盖全部可能，否则编译报错 |
| **case穿透性** | 不存在穿透（各分支完全独立） | 默认执行完匹配的 `case` 即跳出，无需 `break`；可用 `fallthrough` 显式穿透 |
| **多值匹配** | 需使用逻辑运算符（如 `||`） | 允许在一个 `case` 后通过逗号 `,` 连接多个值 |
| **代码可读性** | 适合 1-3 个分支的区间或组合判断 | 适合多分支的等值匹配、状态机转移或枚举流控 |

## 🧱 if 分支语法与实战规范

`if` 语句基于条件表达式的真假来决定大括号内代码块的执行。

### 1. 单分支结构 (if) 与 双分支结构 (if-else)
```swift
let outsideTemperature = 15

// 单分支：仅在条件成立时做某事
if outsideTemperature < 10 {
    print("天气寒冷，建议穿着外套。")
}

// 双分支：互斥逻辑，必须执行且仅执行其中之一
if outsideTemperature >= 28 {
    print("开启制冷空调。")
} else {
    print("关闭制冷空调，保持自然通风。")
}
```

### 2. 多条件分支结构 (if - else if - else)
用于多路可选情况，控制流将从上至下依次匹配，一旦某个分支条件为 `true`，执行完毕后将直接跳出整个 `if` 结构。
```swift
let userRole = "moderator"

if userRole == "admin" {
    print("授予全部系统超级管理权限。")
} else if userRole == "moderator" {
    print("授予内容审核与社群管理权限。")
} else if userRole == "member" {
    print("授予基础发帖与阅读权限。")
} else {
    print("未登录访客，仅限浏览公开内容。")
}
```

### 3. 复合条件与逻辑运算符结合
通过逻辑与 `&&`、逻辑或 `||` 可以在 `if` 语句中实现多重条件的复合判定：
```swift
let memberScore = 85
let hasViolation = false

// 条件：积分大于80 且 无违规记录
if memberScore > 80 && !hasViolation {
    print("符合优秀版主申请条件。")
}
```

## 🎛️ switch 等值匹配与完备性法则

当面对同一个变量的多个固定值匹配时，使用 `switch` 能提供远胜于多层 `else if` 的可读性与执行效率。

### 1. 核心语法模板与多值匹配
在 Swift 中，`switch` 不需要大括号包裹各 `case` 代码块，且每个分支默认隐式包含 `break` 机制，执行完毕后自动跳出，避免了传统 C/C++ 语言由于忘记写 `break` 导致的“穿透”漏洞。
```swift
let itemCode = "B"

switch itemCode {
case "A":
    print("商品类别：生鲜蔬果")
case "B", "C": // 💡 多值匹配：匹配 B 或 C
    print("商品类别：日用百货")
case "D":
    print("商品类别：数码家电")
default:
    print("未知的商品类别代码")
}
```

### 2. 完备性法则 (Exhaustiveness Rule)
Swift 编译器会强制检查 `switch` 语句是否覆盖了被匹配变量的所有潜在可能。
如果被匹配的是常规基础类型（如 `Int`, `String` 等），由于其取值范围近乎无限，必须包含一个 `default` 分支作为捕获所有的保底通道。
```swift
let diceNumber = 4

// ⚠️ 若在此处去掉 default 分支，编译器将报错: 
// "Switch must be exhaustive"
switch diceNumber {
case 1, 2, 3:
    print("属于低点数区")
case 4, 5, 6:
    print("属于高点数区")
default:
    print("非法的骰子点数")
}
```

### 3. switch 与 枚举 (Enum) 的深度配合
在实际工程中，`switch` 最强力的应用场景是与枚举类型配合。
因为枚举的成员是定义好的有限集合，只要我们的 `case` 列表完整映射了枚举的所有成员，**便可免写 default 分支**。这保证了代码的高安全度——当未来枚举新增了成员，而某处的 `switch` 漏写了对应匹配，编译器将直接报错，在开发阶段杜绝隐患。

```swift
// 定义网速测试状态枚举
enum ConnectionStatus {
    case disconnected
    case connecting
    case connected
    case timeout
}

let currentStatus = ConnectionStatus.connected

// 💡 覆盖了枚举全部 4 个 Case，无需 default 分支
switch currentStatus {
case .disconnected:
    print("当前网络已断开，请检查网线。")
case .connecting:
    print("网络正在连接中，请稍候...")
case .connected:
    print("网络已成功建立连接。")
case .timeout:
    print("连接超时，正在尝试自动重连。")
}
```

## 🏁 综合实战演练

以下代码演示了多路条件在实际系统权限与订单结算中的联合应用：

```swift
import Foundation

// 1. 实战：复合条件 if-else
let orderAmount = 150.0
let hasCoupon = true

if orderAmount >= 100.0 && hasCoupon {
    let finalPay = orderAmount - 20.0
    print("满足满减加满折活动，最终支付: $\(finalPay)")
} else {
    print("不符合满减条件，最终支付: $\(orderAmount)")
}

// 2. 实战：Switch 匹配有限状态
enum ServerState {
    case offline
    case active
    case maintenance
}

let serverState = ServerState.maintenance

switch serverState {
case .offline:
    print("服务器当前离线，已向运维组发送警报。")
case .active:
    print("服务器运行正常，负载 12%。")
case .maintenance:
    print("服务器正在维护中，暂停外部用户访问。")
}
```
