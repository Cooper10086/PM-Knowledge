# iOS 基础实战教程：UIImageView 图像渲染与 Retina 适配

`UIImageView` 是 iOS 开发中用于呈现图像资源的控件。在 Retina 视网膜屏幕普及的今天，理解**逻辑点（Points）**与**物理像素（Pixels）**的关系，以及**倍图机制**，是开发清晰、高质量界面的基础。本教程将引导你掌握单图加载、多帧动画以及像素适配。

---

## 一、 UIImageView 与 UIImage 职责划分

*   **`UIImageView`**：继承自 `UIView`，充当“相框”，负责在屏幕上开辟区域、定位（Frame）、控制展示图层与层级。
*   **`UIImage`**：代表底层的“图片二进制数据实体”，负责解析磁盘或网络上的图片并提供像素位图。

```swift
override func viewDidLoad() {
    super.viewDidLoad()
    
    // 1. 创建 UIImageView 实例 (确定相框大小和坐标)
    let logoView = UIImageView(frame: CGRect(x: 50, y: 120, width: 100, height: 100))
    
    // 2. 装载图片实体 (UIImage)
    // ⚠️ UIImage(named:) 是可选初始化器，若资源缺失会返回 nil。加 "!" 代表强制解包。
    let logoImage = UIImage(named: "avatar")! 
    
    // 3. 将图片塞入视图中
    logoView.image = logoImage
    
    // 4. 装载到当前父视图
    self.view.addSubview(logoView)
}
```

## 二、 序列帧动画控制 (Frame-by-Frame Animation)

`UIImageView` 内置了图像数组的播放控制，可用于快速实现简易帧动画：

```swift
override func viewDidLoad() {
    super.viewDidLoad()
    
    let animView = UIImageView(frame: CGRect(x: 100, y: 200, width: 80, height: 120))
    self.view.addSubview(animView)
    
    // 1. 组装 UIImage 帧序列数组 (必须确认为确定的 [UIImage] 类型，不可包含 nil)
    let frameList = [
        UIImage(named: "walk_1")!,
        UIImage(named: "walk_2")!,
        UIImage(named: "walk_3")!,
        UIImage(named: "walk_4")!
    ]
    
    // 2. 注入动画帧数组
    animView.animationImages = frameList
    
    // 3. 配置动画参数
    animView.animationDuration = 0.8  // 播放完一组帧所需的总秒数
    animView.animationRepeatCount = 0 // 循环播放次数，0 代表无限循环
    
    // 4. 启动播放
    animView.startAnimating()
    
    // 停止动画 API: animView.stopAnimating()
}
```

## 三、 逻辑点 (PT) 与 物理像素 (PX) 的深层关系

为了摆脱早先设备分辨率不同导致的布局混乱，苹果引入了**物理点（Point）**概念：

*   **物理点（pt）**：开发中编写的物理数值单位（如 `x: 100`, `width: 320`）。
*   **物理像素（px）**：屏幕上真实存在的物理发光二极管发光像素。
*   **Retina 屏幕关系公式**：
    $$\text{物理像素 (px)} = \text{物理点 (pt)} \times \text{倍率 (Scale)}$$

## 四、 iOS 倍图（@2x & @3x）无损适配原理

苹果利用资源束 `Assets.xcassets`，实现了不同屏幕清晰度设备对图像的**动态按需加载**。

```mermaid
graph TD
    Device[运行期 iOS 设备] -->|识别屏幕 Scale| Match{设备物理倍率}
    Match -->|1x 设备 (老旧已淘汰)| Load1x[加载 1x 图片]
    Match -->|2x 设备 (如 iPhone 8)| Load2x[加载 test@2x.png]
    Match -->|3x 设备 (如 iPhone 13)| Load3x[加载 test@3x.png]
    Load1x --> Render[无拉伸清晰渲染]
    Load2x --> Render
    Load3x --> Render
```

### 1. 资源命名规范
设计师为我们切图时，通常会输出多个分辨率的文件。我们将它们命名为：
*   `pic_name.png` (1x, 可选)
*   `pic_name@2x.png` (2x, 强制)
*   `pic_name@3x.png` (3x, 强制)

### 2. 资产加载逻辑
在 Xcode 中将它们拖拽进 `Assets.xcassets`，在代码中只需使用**基础名称**加载：
```swift
// 系统会自动根据当前运行设备的屏幕倍率，智能挑选加载 pic_name@2x 还是 pic_name@3x
let banner = UIImage(named: "pic_name")!
```

## 五、 章节总结与要点速查

*   **类职责**：`UIImageView` 提供显示容器，`UIImage` 装载图片数据。
*   **解包规范**：图片加载容易因拼写错误失败返回 `nil`，实战中需通过 `!` 解包或 `if let` 绑定安全使用。
*   **倍图适配**：
    *   **2x 设备**：物理点 $100 \times 100$ 的区域，系统会自动读取 $200 \times 200 \text{ px}$ 的 `@2x` 图。
    *   **3x 设备**：物理点 $100 \times 100$ 的区域，系统会自动读取 $300 \times 300 \text{ px}$ 的 `@3x` 图。
    *   **老旧 1x 设备**已于市场绝迹，当前商业开发仅需适配 `@2x` 和 `@3x` 即可。
